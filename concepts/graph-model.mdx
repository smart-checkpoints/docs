A road network is stored as a graph. Enforcement is a property of an edge, not
of a camera.

Adding a checkpoint means adding a node and declaring which existing nodes it
connects to. Everything downstream follows from the shape of the graph. Two
cameras with no edge between them enforce nothing, however close they are.

## The two ids of a node

Every node has two identifiers, and different parts of the system use different
ones.

| Field | Scope | Used by |
| --- | --- | --- |
| `node_id` | Unique across the whole server | Edges, in `from-node-id` and `to-node-id` |
| `id_in_project` | Index inside one project, from zero | `/report-checkpoint`, and the distance driver protocol |

Cameras and drivers speak in project indices, so they never need to know
anything about other projects on the same server.

## Coordinates

Every coordinate in the system is WGS84 degrees, always. The server rejects
anything outside latitude &plusmn;90 or longitude &plusmn;180 on the way in,
because that check is the only thing standing between a typo and enforcement
built on a wrong position.

Nodes carry latitude and longitude only. There is no altitude.

## The rule

An edge carries two numbers, and those two numbers are all the logic needs.

```
minimum legal traversal time (s) = distance (m) / speed limit (km/h) * 3.6

average speed (km/h) = distance (m) / elapsed time (s) * 3.6
```

A run is a violation when it crossed the edge in less time than the limit
allows. Distances are always metres and speed limits are always km/h. A driver
that answers in kilometres, or a limit entered in mph, produces violations that
look perfectly normal.

## Resolved and unresolved edges

An edge does not always have a distance. Whether it does is a stored fact, not
an inference: every edge carries a `distance_status`.

| `distance_status` | Meaning | Enforcement |
| --- | --- | --- |
| `ok` | A driver routed it, or an operator typed it | Runs normally |
| `unknown` | Nobody has answered yet, or a driver failed transiently | Skipped. The edge is shown as not enforcing |
| `no-route` | A distance driver said there is no road here | Skipped. Flagged as a data error |

`distance` is `null` whenever the status is not `ok`, and a `distance` of `0` is
rejected on the way in. Both the violation path and the congestion figure skip
any edge whose status is not `ok`.

<Note>
  A missing distance driver fails quietly rather than loudly, but visibly: the
  edge sits at `unknown`, the console draws it with a broken stroke, and no
  vehicle it carries is ever judged. The server never substitutes a
  straight-line estimate for a road distance nobody measured, because a
  plausible wrong distance produces violations that look exactly like real ones.
</Note>
