---
title: "Data model"
description: "The SQLite tables behind the graph."
---

The server stores everything in one SQLite file, `database.db`, created next to
`server.js` on first run. The schema is created and migrated at startup, and a
failed migration stops the server rather than letting it serve wrong positions.

## Tables

<AccordionGroup>

    | --- | --- | --- |
    | `project_id` | INTEGER | Primary key |

    | `api_key` | TEXT | 32 characters, generated on creation |
    | `node_count` | INTEGER | |
    | `connection_count` | INTEGER | |
  </Accordion>

  <Accordion title="nodes" icon="location-dot">

    | Column | Type | Notes |

    | `node_id` | INTEGER | Primary key, unique across the server |

  <Accordion title="connections" icon="arrows-left-right">

  <Accordion title="car_data" icon="car">

    | Column | Type | Notes |
    | --- | --- | --- |
    | `car_id` | INTEGER | Primary key |
    | `project_id` | INTEGER | |
    | `car_plate` | TEXT | |

    | `last_sighting_node_id` | INTEGER | References `nodes.node_id` |
  </Accordion>

  <Accordion title="violations" icon="triangle-exclamation">
    A recorded violation. Append only.

    | Column | Type | Notes |
    | --- | --- | --- |
    | `violation_id` | INTEGER | Primary key |
    | `project_id` | INTEGER | |
    | `car_plate` | TEXT | |

  <Accordion title="traversals" icon="stopwatch">

    | `delta_t` | REAL | Elapsed seconds across the edge |
    | `timestamp` | TEXT | ISO 8601 UTC |
  </Accordion>

## Retention

`traversals` is the only table the server prunes, and only to the last five
minutes. `violations` grows without bound, and `car_data` holds one row per plate
that has ever been seen by the project.

<Note>
  A violation records the plate, the average speed, and the time. It does not
  record which edge it happened on. If you need that, read it from the
  `traversals` row with the matching timestamp.
</Note>

<Warning>
  Every timestamp in a TEXT column is ISO 8601 in UTC, which is also what the
  REST API accepts and what the realtime events carry. Databases created before
  this hold `violations.timestamp` as stringified epoch milliseconds, such as
  `"1787905380236.0"`, which no client can parse back into a time. Rows
  written from now on are ISO; old rows are left as they are, and the console
  reads both.
</Warning>
